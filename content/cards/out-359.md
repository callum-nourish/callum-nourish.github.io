Update milestone status via “Update Progress towards a Milestone” interaction

When updating a Milestone via a “Update goal progress” interaction, I want to be able to keep its status as _In Progress (Default)_, or change it to _Completed_, or _Archived_, so its state is clearly tracked and displayed within the goal.

**Acceptance Criteria**
- When updating the progress on a milestone via an interaction the default status choice should be the equivalent radio button to the current milestone status.
- The status of a milestone should only be changed if the user selects a status different to the current milestone status and then applies that selected status on save if different.
- The milestone status updated by the interaction should be updated in real time in both the timeline list of saved interactions and the side panel view open in the other browser tab. (this logic for updating the side-panel is already implemented due to creating a key/value pair in browser local storage which this tab recognises).
### Optimisation
- When updating in realtime, we ideally want to leverage a pre-existing endpoint that fetches the singular milestone's status after it's been updated. In the side panel drawer tab it would use the same endpoint but also utilise the parameter to include interaction_ids too.
### Priority changes 04/11/25
- Leave the "Update progress" button active if a milestone is complete.
- When the user selects complete or archive in the interaction, it will update the milestone status. It should update the in progress status too as the current milestone status might be "complete" if the user selects the "Update progress" button on a "Complete" milestone to revert it back to in progress.
- If a milestone is archived, the "Update progress" button should be disabled. This functionality may already be implemented. When the update progress button is disabled, there should be a button to explicitly unarchive the milestone so the user would not be blocked.
