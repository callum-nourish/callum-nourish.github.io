We want to gather reports - related data that will allow us to decide if having a frontend reports processor worth it and what the requirements should be for that (out of scope tho)
### Reports
These three places are where we should log details from
1. Rendering of html, csv and excel reports  
2. Rendering of temp files (html)
3. Rendering from temp files html > pdf (pdf rendering)
Errors are logged by appsignal > we just want to log successful ones
### What do we want to know from reports?
When a report class starts to become too large in render time duration
When a report has been sat in the queue for a long time

1. We want to track the render time for the report class + report format
	1. HTML reports
	2. Temporary HTML reports
	3. HTML to PDF reports
2. We want to track the time the reports spends in the job queue over time for each report class + report format
3. queue wait time from html to pdf over time
4. A gauge for live queue wait time average
5. Number of models queried against each report class

#### Acceptance Criteria
For each report we want
- Report size (MB)
- Report format
- Report class (type)
- Number of models queried 
	- We will have to make query function within the render public as it's currently private
- Report generated (success/failure)
