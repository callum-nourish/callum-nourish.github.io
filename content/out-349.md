Add an “Activity Log” section inside Milestones in the side panel to give users and overview of all the updates/progress that has been added towards that milestone ans tehrefor the PWS goal. Each activity record should come from interactions linked to taht milestone and should include: the name of the interaction, date added, support worker that added it, time spent (only for Update progress interaction) and a short description of the activity (only for Update progress interaction)

As a user, I want to easily visualise a summary of all the work that has been done with a PWS to contribute and progress towards each of their goals

As a user, I want to easily visualise who are the support workers that have been working witha PWS on each of their milestones and how long they have spent on each activity

!

#### Questions
1. Add section called Activity Log within a Milestone to display all interactions linked to that milestone
2. Add in brackets next to the header the number of interactions linked to that milestone (including update milestone and others)
3. If there are not yet any linked interactions, the headers for this section should display as “Activity Log (0)”
4. Each Milestone should display a list view of interactions linked to it. based on [https://nourishcare.atlassian.net/browse/OUT-343](https://nourishcare.atlassian.net/browse/OUT-343) [https://nourishcare.atlassian.net/browse/OUT-363](https://nourishcare.atlassian.net/browse/OUT-363)
5. This should include both the “Update Milestone” interaction for Milestones and any other interactions linked to it.
6. Each interaction record should include the following information (as per the designs attached):
    1. Interaction name
    2. Interaction close date
    3. Time spent (only for Update progress interaction) - param on the interaction
    4. Carer name who submitted the interaction - closer on interaction
    5. Two line description of the activity (only for Update progress interaction) - First 2 lines of text added to the parameter “What has Frank done today in line with this <milestone_term>?” - do we want this to expand? (not needed if we can click to see the full interaction)
7. Interaction on the activity log should be displayed in descending order (newest >oldest)
8. Add pagination under activity log as per designs - pagination should appar when there are more than 5 interaction logs per screen
9. User should be able to click through and open the interaction from the card. This should open the interaction in a separate tab

NOTE: serialize all this in the milestone serializer with an extra filter “extended”. Use on the milestone/:id GET

#### References

**Acceptance Criteria**
- The **Activity Log** section appears within each Milestone’s side panel as per designs.
- The section is displayed as “Activity Log (0)” when no interactions are linked to the milestone.
- When displayed, the **header** includes the total count of linked interactions in brackets, e.g. Activity Log (3)
- The Activity Log displays **all interactions linked to the milestone**, including:
    - “Update Milestone” interactions.
    - Any other linked interactions.
- The list is **sorted by interaction close date**, with the **newest interactions first** (descending order)
- If there are **more than 5 interaction records**, **pagination controls** are displayed below the list.
- Each page displays **up to 5 interactions**.
- The total interaction count in the header remains consistent across pages.
- Pagination behavior matches existing design patterns used elsewhere in the application.
- Clicking an interaction card opens the full interaction view in a new browser tab.

For all interactions:
- Interaction name.
- Interaction close date.
- Carer (support worker) name who submitted or closed the interaction.

For “Update Milestone” interactions only, also display:
- Time spent (from the interaction parameter).
- A short description of the activity (the first two lines of text from the parameter _“What has Frank done today in line with this <milestone_term>?”_).
    - The description is truncated to two lines with an ellipsis if longer.

For other interaction types:
- Time spent and description are not displayed.
