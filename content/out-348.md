**Task**: Implement Filter “Chips” for Goals by Status within each filter category as implemented in [OUT-319](https://nourishcare.atlassian.net/browse/OUT-319)

**Objective**: Enable users to manage filter for specific statuses within each goal filter category (All goals, Active Goals, Past Goals) This will enhance user experience by enabling users to view goals that meet their specific needs

**Status Chips to Implement**:
- Not Started
- In Progress
- Completed
- Archived

**Relevant Categories for each status**
- **All Goals** - Includes all statuses: Not started, In progress, Completed, Archived
- **Active Goals** - Shows goals statuses: Not started, In progress,
- **Past Goals** - Shows goals statuses: Completed, Archived
    
**Acceptance Criteria**:
- Users can select/deselect status filters via clickable chips.
- When All Goals is selected 
	- we should display all goals across and the filter chips for statuses for the available goals
- When Active Goals is selected - we should only display goals and filter chips for statuses Not started and In progress for the relevant goals 
- When Past Goals is selected - we should only display goals and filter chips for statuses Completed and Archived for the relevant goals 
- Chip selection/deselection update the goal list in real-time
- Deselected statuses are shown with a different visual treatment to make clear they are not selected.
- Unit tests must cover each status filter option.
- The filter should be accessible from the goal list view.
- Follow current design patterns in the UI for consistency.
- Show pulse chips only if there are goals available in that status; E.g. if we don't have any goals "in progress" as dictated in the useGoalFilter file, we don't show the "In progress" chip at all.
- Reset filter selections to default on page refresh
- When a new goal is added/changes status, the chip should be added in real time (e.g. when the first goal is completed or archived for a user, the relevant chip should be made available in the filter)
    
- If no goals have been created, we should display the screen created in [[OUT-335]]
