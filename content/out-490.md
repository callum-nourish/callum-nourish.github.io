**Requirements**
- Add role settings for “Custom Critical Information” in the Roles section (screenshot below), under “Carers”
  
        
        - “Full access” - can edit setting to customise critical information and see/access this section in the admin panel
            
        - “No access” - cannot edit the critical information settings or see/access this section in the admin panel
            
- This permission should control who can configure the Critical Information dashboard at the Organisation Unit level (i.e. which fields are displayed).  
    It does not control who can view the Critical Information dashboard or who can edit the underlying data in assessments, care plans, or interactions.
    
- This permission should be configurable within the existing Role & Permissions management area, alongside other administrative permissions.
    
- Permissions should apply per Organisation Unit, allowing different services within the same organisation to control access independently.  
    Changes to permissions in one Organisation Unit should not affect others.
    
- For existing customers, the permission will be automatically enabled for all Admin roles upon release. No changes will be applied to non-Admin roles unless explicitly configured by an Admin user.
   
- This work should be under the FT custom_critical_information created on [https://nourishcare.atlassian.net/browse/OUT-508](https://nourishcare.atlassian.net/browse/OUT-508)
    

### ❓ Problem

As a Registered Manager, when I view the Critical Information dashboard for a person we support, I want the information displayed to reflect what is truly critical for my service and care setting, so my team can access the right information quickly and safely.

As an Admin user, when configuring my Organisation Unit, I want to control which roles can edit the Critical Information dashboard settings, so we can maintain consistency, governance, and relevance across our service.

### Out of scope

_Permissions for viewing interactions where the inforation for critical info is edited_

### ✅ Acceptance Criteria / Definition of Done

- A new permission exists that controls access to edit Critical Information configuration at the Organisation Unit level
    
- “Custom Critical Information” permission settings added for all roles under “Carers” using icon added below
    
    
    - “Full access” - can edit setting to customise critical information and see/access this section in the admin panel
        
    - “No access” - cannot edit the critical information settings or see/access this section in the admin panel
        
    
    - Enabled by default for Admin roles (Full access)
        
    - Disabled by default for all non-Admin roles (No access)
        
    
    - Cannot access or edit Critical Information configuration settings
        
    - Can still view the Critical Information dashboard (if they otherwise have access)
        
- The permission is configurable via Role & Permissions management
    
- Work is under the FT custom_critical_information
