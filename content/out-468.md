Ensure a smoother user experience when the **Milestone Progress interaction** is hidden, disabled, or not applicable.  

Currently, if this interaction type is unavailable or not applicable (if G&M toggle off) , users may still attempt to access or search for it, which can lead to confusion.
## Unanswered Questions
A *Milestone Progress* interaction would be "hidden" when the user has no in progress milestones or the interaction doesn't exist... Yet it says here "hidden or disabled". What scenario would this interaction be disabled?

## User Stories
When a user is trying to update progress for a milestone from the drawer, I want to be informed when the *Milestone Progress* interaction is unavailable, so I understand why I cannot access it...

When a user is searching for interactions in the Timeline, I should not see the *Milestone Progress* interaction if the client has no milestones created,  so my search results remain relevant and uncluttered.

#### Visibility on Timeline Search
- The Milestone Progress interaction should not appear in the list of available interactions in the Timeline search when the user has no milestones created.
- If milestones are later created, the interaction should automatically become visible again in the search options.
